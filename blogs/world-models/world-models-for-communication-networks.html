1. CoDreamer: Communication-Based Decentralised World Models

论文信息： Edan Toledo and Amanda Prorok, 2024 arXiv preprint。arXiv abstract · PDF

这篇论文想解决什么问题？

这篇论文研究的是多个智能体怎样一边学习环境，一边相互配合。这里的 agent（智能体） 可以理解成独立观察环境并采取行动的机器人或游戏角色。

单个 agent 通常只能看到环境的一小部分。例如，一台机器人看得到自己附近的障碍物，却不知道远处队友正在做什么。每个 agent 如果只根据自己的视角预测未来，其他 agent 的行动就会像无法解释的环境变化，使预测很容易出错。

作者希望解决的问题是：能不能让 agents 交换信息，共同建立一个更准确的 World Model，并据此学会合作？

这里的“communication”是 agents 在算法内部交换信息，并不是在研究无线信道、带宽或通信协议。

作者具体怎么做？

论文以 Dreamer 为基础。Dreamer 的基本思路并不复杂：

  • 先让模型观察真实环境，学习一个能够概括当前情况的内部状态。

  • 再让模型从这个内部状态出发，“想象”未来几步可能发生什么。

  • 最后使用这些想象出来的经历训练决策，而不必每一步都回到真实环境中试错。

Dreamer 中负责保存和更新内部状态的部分叫 RSSM。可以把 RSSM 简单理解为模型的“记忆”：它把过去看到的内容和刚刚发生的事情压缩成一份较短的状态表示。

作者先实现了一个不通信的版本 IDreamer。在这个版本中，每个 agent 都用自己的观察建立 World Model，彼此不交换信息。

随后，作者提出 CoDreamer，在两个地方加入通信：

  • 建立 World Model 时通信。 每个 agent 把自己的内部状态与附近 agents 的状态结合起来，用于预测接下来会发生什么。

  • 作决策时通信。 每个 agent 在选择行动和判断行动好坏时，也参考附近 agents 的信息。

负责汇集邻居信息的模块叫 GNN（Graph Neural Network，图神经网络）。在这里，每个 agent 是图上的一个点；两个 agents 距离足够近时就在图中连接。GNN 做的事情，可以粗略理解为“让每个 agent 看一眼邻居发来的信息，再更新自己的判断”。

决策部分还出现了两个常用词：

  • Actor 负责选择下一步做什么。

  • Critic 负责估计这个选择长期来看有多好。

实验具体怎么做？

作者在两组多智能体任务上进行了实验。

第一组是 VMAS，观察是位置、速度等数值：

  • Flocking：4 个 agents 一起保持队形移动。

  • Discovery：5 个 agents 合作探索目标。

  • Buzz Wire：2 个 agents 配合完成移动任务。

每个 agent 有 5 种可选动作，每局最多运行 500 步。

第二组是 Melting Pot，agent 看到的是 64 × 64 的局部画面：

  • Daycare：2 个 agents。

  • Cooperative Mining：4 个 agents。

  • Collaborative Cooking–Asymmetric：2 个 agents。

  • Collaborative Cooking–Forced：2 个 agents。

这些任务要求 agents 分工或配合；只看自己的局部画面，通常无法判断整个团队正在发生什么。每个 agent 有 8 种可选动作。

作者主要比较三种方法：

  • IPPO：不学习 World Model，直接从真实经验中学习。

  • IDreamer：每个 agent 有自己的 World Model，但不通信。

  • CoDreamer：既有 World Model，也允许 agents 交换信息。

每种方法在每个任务上使用 500,000 个真实环境步骤训练，并独立重复 4 次。Dreamer 类方法每次会在模型内部想象未来 15 步，用这些虚拟经历继续训练。

实验结果怎样？

在 VMAS 的数值观察任务中，CoDreamer 的总体成绩最好，但领先幅度不大；有些结果的误差范围仍然重叠。这说明在相对简单、信息较充分的任务中，通信并不一定带来很大的提升。

在 Melting Pot 的局部图像任务中，差距更明显。论文把不同任务的成绩换算到 0 到 1 之间，1 表示接近该任务的最好成绩。综合多次实验后：

  • CoDreamer 的代表性综合成绩约为 0.48。

  • IDreamer 约为 0.30。

  • IPPO 约为 0.05。

这说明当每个 agent 能看到的信息很少、又必须与别人配合时，让 World Model 汇集邻居信息确实有帮助。

不过，CoDreamer 在想象未来时没有同时预测 agents 之间的连接关系会怎样变化。它直接沿用想象开始时的连接图。因此，这些结果还不能说明它能处理连接快速变化、存在延迟或丢包的真实通信网络。

2. Efficient Information Sharing for Training Decentralized Multi-Agent World Models

论文信息： Xiaoling Zeng and Qi Zhang, Reinforcement Learning Journal（RLC 2025）。paper page · PDF

这篇论文想解决什么问题？

这篇论文也研究多个 agents，但问题更加具体：如果每个 agent 都有自己的 World Model，训练时应该互相分享什么？如果不能把所有数据都发出去，又应该优先分享哪些数据？

作者把可以分享的信息分成两类：

  • agents 在真实环境中收集到的经历。

  • World Model 自己想象出来的未来经历。

这里的 experience（经历） 就是一条训练记录，例如“当时看到了什么、采取了什么行动、得到了多少奖励、后来发生了什么”。

作者具体怎么做？

每个 agent 都有独立的 World Model 和决策模型，但训练时可以使用其他 agents 分享的数据。

第一种做法是分享真实经历。不同 agents 把经历放进一个共同的 replay buffer（经验库）。经验库就像保存训练记录的资料夹，模型会反复从里面抽取旧记录学习。作者只让 agents 共同学习环境变化、奖励和任务是否结束等规律；与每个 agent 自己视角有关的图像重建部分仍然分别学习，避免不同视角混在一起。

第二种做法是分享想象经历。每个 agent 先用自己的 World Model 生成一段未来过程，再把这段虚拟记录交给其他 agents。其他 agents 可以使用这些记录训练 Actor 和 Critic。

如果只能分享少量数据，作者会根据 loss（误差） 选择样本。模型对某条经历预测得越不准，这条经历的 loss 就越大，也就越值得分享。直观地说，系统优先发送模型觉得“意外”或“困难”的样本，而不是随机发送。

论文中的 bandwidth 需要特别说明。它表示“允许分享的样本占全部样本的比例”，例如 0.05 表示只能分享 5% 的样本；它不是通信系统里常说的 bit/s，也没有真的模拟数据包、传输时延或信道错误。

实验具体怎么做？

实验使用 SMAC，即一个基于 StarCraft II 的多智能体合作环境。每个 agent 控制一个战斗单位，所有单位要互相配合击败对手。

作者选择了四个小型战斗任务：

  • 2s_vs_1sc

  • 2m_vs_1z

  • 3m

  • 2s3z

这些名字表示双方单位的数量和类型。理解实验时不必记住每个缩写，重点是：多个己方单位必须合作，而每个单位只能看到局部情况。

每种设置独立运行 10 次。World Model 每次使用连续 20 步的真实记录学习，并在内部想象未来 15 步。

作者比较了三种训练方式：

  • Independent Training：每个 agent 只使用自己的数据。

  • Centralized Training：所有可用数据都集中在一起训练。

  • Selective Sharing：只分享经过挑选的真实经历或想象经历。

为了研究分享多少数据合适，作者还测试了 1%、5%、10%、50% 和全部分享等不同设置。

实验结果怎样？

在不限制分享量时，分享真实经历和分享想象经历都比完全独立训练更好。这说明一个 agent 收集到的数据确实能帮助另一个 agent 学习。

更有意思的是，在限制分享量的实验中，只分享一小部分高误差样本，有时反而比全部分享更好。作者最后在不同任务中采用了约 1% 或 5% 的分享比例。

原因可能是：并非所有数据都同样有用。大量容易、重复的样本会占用训练资源，而模型尚未学会的样本更能推动它改进。

不过，把“分享真实经历”和“分享想象经历”同时使用，并没有稳定地得到两者效果之和。论文也没有把样本换算成实际传输字节，因此它说明的是“怎样筛选训练数据”，还不能直接回答真实网络需要多少带宽。

3. Dreamer-CPC: Message Learning with World Models for Decentralized Multi-Agent Reinforcement Learning

论文信息： Taisuke Takayama, Naoto Yoshida, and Tadahiro Taniguchi, arXiv preprint, 2026。arXiv abstract

这篇论文想解决什么问题？

很多多智能体算法会让 agent 根据“当前看到的内容”生成一条 message 发给队友。但有些重要信息只在更早的时候出现过，当前画面中已经看不到了。

例如，一个 agent 先看到目标在左边，几步之后目标被障碍物挡住。这时它的当前画面里已经没有目标；如果 message 只来自当前画面，它就很难把“目标之前在左边”告诉队友。

这篇论文想解决的问题是：能不能让 agent 根据 World Model 保存的历史记忆来生成 message，而不是只根据眼前的一帧画面说话？

作者具体怎么做？

每个 agent 都使用 DreamerV3，并通过 RSSM 保存过去信息。作者另外加入一个能够记住先前 message 的小型循环模型，让 agent 根据自己的 World Model 状态和先前通信历史生成新 message。

message 不是一句自然语言，而是一组离散符号。论文测试了两种形式：

  • 从 20 个符号中选择 1 个。

  • 连续选择 4 次，每次从 5 个符号中选 1 个。

两种形式可能表达的组合数量相近，但后一种形式可以把一条 message 拆成几个较小的部分。

方法名称中的 CPC 是一种学习通信符号的训练方法。它不需要人工规定“符号 1 代表向左”或“符号 2 代表向右”，而是让 agents 在完成任务的过程中自己学出哪些符号有用。

接收方得到 message 后，会把它与自己的观察和记忆合在一起，再更新 World Model 并选择行动。

实验具体怎么做？

作者设计了两个只有 2 个 agents 的任务。两个 agents 分工非常明确：Agent 1 负责看到关键信息并发送 message，Agent 2 负责真正行动。

第一个任务叫 Observer：

  • 环境是一张 4 × 4 的格子图。

  • Agent 1 能看到奖励藏在哪里，但不能亲自去拿。

  • Agent 2 能看到自己的位置，却看不到奖励位置。

  • Agent 2 有 6 种动作；在正确位置挖掘得到 +1，其他步骤得到 -0.01。

  • 每局最多 200 步。

第二个任务叫 CatchApple：

  • 环境是一张 8 × 8 的格子图。

  • 一个物体会从上方向下落，途中可能斜着移动或碰到边界后反弹。

  • Agent 1 先观察物体的运动，Agent 2 控制地面的接取位置。

  • 物体在下落过程中会暂时不可见，所以 agents 必须依靠先前记忆推测它最后落在哪里。

  • Agent 2 可以不动、向左或向右；接到物体得到 +1，否则每步得到 -0.01。

  • 每局最多 500 步。

作者比较了：

  • Dreamer-CPC：使用 World Model 的历史状态生成 message。

  • IPPO-CPC：也会通信，但没有 World Model 帮助保存和预测历史。

  • 完全不通信的 IPPO 和 Dreamer。

  • 直接把观察分享给另一个 agent 的方法。由于它获得的信息最多，可以看作一个理想化上限。

每种方法独立运行 10 次。

实验结果怎样？

在 Observer 中，直接分享观察的方法综合成绩约为 53.63；Dreamer-CPC 的两种 message 设置分别约为 39.85 和 19.72；IPPO-CPC 约为 6.81 和 7.31；不通信的方法接近 0。

在 CatchApple 中，直接分享观察约为 38.21；Dreamer-CPC 约为 28.53 和 20.47；IPPO-CPC 约为 5.52 和 4.98；不通信的 Dreamer 约为 5.93。

这些结果表明，当关键线索会从当前观察中消失时，从 World Model 的记忆生成 message 明显优于只依赖当前观察。不过，实验只有两个 agents，而且是专门设计的小型格子任务。论文没有测试真实链路的带宽、延迟和丢包，也没有解释每个离散符号最后学出了什么含义。

4. Continual Deep Reinforcement Learning for Decentralized Satellite Routing

论文信息： Federico Lozano-Cuadra et al., IEEE Transactions on Communications, 2025。IEEE Xplore · arXiv open version

这篇论文想解决什么问题？

这篇论文直接研究低轨卫星网络中的路由，但它不是 World Model 论文。

当一颗卫星收到数据包时，需要选择下一颗卫星，把数据包逐步送到地面目的地。传统最短路算法通常需要比较完整、及时的全网信息；但低轨卫星一直运动，连接和拥塞情况也不断改变，集中收集全网状态会产生额外开销。

作者希望让每颗卫星只依靠本地和附近的信息，自己决定数据包的下一跳，并在网络运行期间持续适应新的拥塞和拓扑情况。

作者具体怎么做？

每颗卫星做决定时会看到：

  • 数据包的目的地。

  • 自己当前的位置。

  • 当前可用的最多 4 条星间链路。

  • 相邻卫星的位置。

  • 四个一跳邻居的大致队列拥塞情况。

可选动作就是从最多 4 个邻居中选择一个作为下一跳。

训练时，系统会根据结果给出奖励：

  • 队列越拥塞，奖励越低。

  • 把数据包送得更接近目的地，奖励越高。

  • 成功送达会得到额外奖励。

  • 形成环路或选择无效链路会受到惩罚。

论文使用 Double DQN。DQN 可以理解为一个打分网络：输入当前情况后，它为每个候选下一跳估计一个“长期分数”，卫星再选择分数较高的方向。Double DQN 是一种减少分数被高估问题的改进版本。它直接学习“什么动作更好”，并不学习一个可以预测未来网络状态的 World Model。

作者先在地面集中训练一个初始模型，再把小型 DQN 上传到每颗卫星。卫星在运行时使用本地数据继续学习。

论文还使用两种参数共享方式：

  • Model Anticipation：把一颗卫星已经更新过的 DQN 参数交给轨道上随后到达相似位置的卫星。这里的 model 指 DQN 参数，不是 World Model。

  • Federated Learning：先在同一轨道平面内平均多颗卫星的模型参数，再进行全局平均。原始训练记录不必全部集中上传。

实验具体怎么做？

作者在四种低轨卫星星座上进行仿真：

  • Kepler：7 个轨道平面，每个平面 20 颗卫星，共 140 颗，高度 600 km。

  • Iridium Next：6 × 11，共 66 颗，高度 780 km。

  • OneWeb：36 × 18，共 648 颗，高度 1,200 km。

  • Starlink：72 × 22，共 1,584 颗，高度 550 km。

实验设置了 2 到 8 个地面 gateway。链路带宽设为 500 MHz，每个数据包大小为 64.8 kbit。

作者比较了：

  • 能够获得实时全网信息的 Dijkstra 最短路算法。它是一个性能很强、但信息要求较高的参照。

  • 传统的表格型 Q-routing。

  • 论文提出的 Double DQN 路由方法。

实验分成几部分：

  • 在没有拥塞时，观察算法从随机尝试逐渐学会接近最短路径需要多久。

  • 增加业务负载，观察算法会不会绕开拥塞队列。

  • 运行完整的 96 分钟轨道周期，每 15 秒更新一次卫星位置和 gateway 连接。

  • 让每颗卫星在本地继续训练，再检查不同卫星的模型是否逐渐变得不一致，以及参数共享能否重新对齐它们。

实验结果怎样？

在无拥塞实验中，Double DQN 和 Q-routing 最终都接近最短路算法。论文图中的收敛时间，在 Kepler 和 OneWeb 中约为 2 秒，在 Iridium Next 中约为 4 秒，在 Starlink 中约为 1 秒。这里的“秒”是仿真里的数据包到达时间，不是现实中训练电脑花费的时间。

在 Kepler 的 8-gateway 实验中，与实时全网最短路相比，Double DQN 的端到端延迟差距在第 50、90 和 95 百分位分别为 1.7、3 和 9.1 ms。业务负载升高时，它会选择传播距离稍长但队列较空的路线，而不是一直挤在固定最短路径上。

在完整轨道周期中，Double DQN 多数时间仍能保持接近最短路的延迟。传统 Q-routing 没有使用卫星位置特征，拓扑变化后往往需要重新探索。

本地持续训练会使各卫星的 DQN 逐渐不同；Model Anticipation、轨道平面内参数平均和全局参数平均都能提高模型的一致性。

这篇论文说明了分布式强化学习可以用于动态卫星路由，但它没有预测未来拓扑、链路或队列，也没有用想象轨迹训练，因此不能把它当成卫星 World Model 的实验结果。

5. NetWorld: Communication-Based Diffusion World Model for MARL in Wireless Networks

论文信息： Kechen Meng, Rongpeng Li, Yansha Deng, Zhifeng Zhao, and Honggang Zhang, arXiv preprint, 2026。arXiv abstract · PDF

这篇论文想解决什么问题？

NetWorld 直接把 World Model 用在无线网络资源分配中。

无线网络有很多不同的控制任务，例如为用户分配时频资源、调整发射信号，或者给不同业务分配网络资源。通常，每换一种任务就要重新收集大量数据并训练一个新模型。

作者希望先从多个旧任务中学习一个较通用的 World Model。遇到新任务时，只提供少量新数据，模型就能较快适应，而不必从头开始。

作者具体怎么做？

NetWorld 学习的不是“给定当前状态，下一步状态是什么”这样的一步预测，而是一小段未来状态变化。它使用 diffusion model（扩散模型） 生成这段未来。

扩散模型的直观工作方式是：

  • 先从一段随机噪声开始。

  • 经过多次逐步修改，把噪声变成一段看起来合理的未来轨迹。

  • 在生成过程中，额外引导模型偏向预期回报更高的轨迹。

由于不同无线任务的输入数值范围差异很大，NetWorld 先用各任务自己的 scenario encoder 把原始观察转换到相同格式的内部空间。可以把 encoder 理解成“翻译器”：它把不同任务的数据翻译成 World Model 能共同处理的表示。

World Model 生成未来状态后，inverse dynamics model（逆动力学模型） 再反推要采取什么动作，才能从当前状态走向预测的下一个状态。

每个 agent 还会参考一跳邻居的平均信息。论文称这种做法为 mean field：它不逐个处理所有邻居的完整状态，而是把邻居影响压缩成一个平均摘要，从而减少模型复杂度。

执行时，模型虽然会规划未来几步，但只执行第一步。得到新的真实观察后，它会重新规划。这种方式叫 receding horizon（滚动规划）。

实验具体怎么做？

作者使用了三个无线网络任务：

  • Coordinated Beamforming（协同波束成形）：19 个 agents 协调发射信号，在提高传输速率的同时减少相互干扰。

  • Resource Block Allocation（资源块分配）：8 到 9 个 agents 分配时频资源。

  • Network Slicing（网络切片资源管理）：19 个 agents 为不同业务分配资源，以满足各自的服务要求。

三个任务的观察、动作和奖励形式差异很大，因此适合用来测试一个模型能否跨任务迁移。

实验每次把其中一个任务留作新任务，并进行以下训练：

  • 先在另外两个旧任务上预训练。每个旧任务有 100 条高质量轨迹，每条 5,000 步。

  • 新任务只提供 10 条轨迹，每条同样是 5,000 步。

  • 使用这些少量新数据训练新任务的 encoder 和 inverse dynamics model，并对 World Model 做轻量调整。

作者把 NetWorld 与四种离线多智能体强化学习方法比较：MA-CQL、MA-IQL、MA-DT 和 MA-DD。这些对比方法都直接使用新任务的 300 条轨迹训练。

这里的 offline（离线） 表示算法从已经收集好的历史数据中学习，而不是一边在线运行一边自由探索。论文中的高质量轨迹来自表现较好的已有策略。

每次评估运行 1,000 步，比较平均奖励。所有结果独立运行 3 次。

实验结果怎样？

NetWorld 在三个任务上的最终平均奖励都高于四种对比方法。它在新任务中只使用了 10 条轨迹，也就是 50,000 个步骤；对比方法使用 300 条轨迹，也就是 1,500,000 个步骤。

因此，从“新任务需要多少数据”来看，NetWorld 只用了对比方法的约三十分之一，并取得了更好的结果。

不过，这不能理解成 NetWorld 的全部训练数据也减少了三十倍。它在两个旧任务上已经使用了 1,000,000 个步骤进行预训练，加上新任务数据后，总量约为 1,050,000 步。论文真正证明的是：旧任务中学到的知识可以迁移，从而减少新任务所需的数据。

实验只重复了 3 次，也没有报告扩散模型每次规划需要多少实际时间和计算量，更没有测试真实无线链路中的丢包、传输延迟或能耗。因此，目前的结果主要说明算法在仿真数据上的跨任务迁移能力。

6. MARIE: Decentralized Transformers with Centralized Aggregation

论文信息： Yang Zhang, Chenjia Bai, Bin Zhao, Junchi Yan, Xiu Li, and Xuelong Li, Transactions on Machine Learning Research, April 2025。arXiv abstract · OpenReview

这篇论文想解决什么问题？

建立多智能体 World Model 时有一个两难问题。

如果用一个大模型同时处理所有 agents，它能看到全局信息，却会随着 agent 数量增加而迅速变得庞大、难以训练。如果每个 agent 完全独立建模，模型比较简单，却看不到其他 agents 对自己的影响。

MARIE 希望兼顾两者：每个 agent 主要预测自己的局部未来，同时在训练时获得一份由全体 agents 信息形成的全局摘要。

作者具体怎么做？

MARIE 主要由三个部分组成。

第一部分是 VQ-VAE。它把每个 agent 看到的连续数值或图像压缩成 16 个离散 tokens。这里的 token 不是单词，而是模型为一小段观察内容分配的数字编号。这样做可以把不同长度、不同维度的观察统一成固定数量的紧凑符号。

第二部分是 Transformer。Transformer 是一种擅长处理前后顺序的模型。它读取某个 agent 过去的观察和动作 tokens，预测这个 agent 下一步会看到什么、得到多少奖励，以及任务是否结束。

第三部分是 Perceiver。它在训练时读取所有 agents 当前的观察和动作，再为每个 agent 生成一份较短的全局摘要。每个局部 Transformer 因而既能关注自己的历史，也能知道团队整体正在发生什么。

训练决策模型时，MARIE 使用 World Model 生成想象经历。真正部署到环境中时，只运行已经学好的轻量决策模型，不再运行 VQ-VAE、Transformer 和 Perceiver。也就是说，MARIE 的 World Model 是训练工具，而不是部署后每一步都要携带的模块。

实验具体怎么做？

主要实验仍然使用 SMAC 的多智能体合作战斗任务。作者选择了 13 张难度不同的地图，并严格限制能够从真实环境中获得的训练步骤：

  • 简单地图最多使用 100,000 步。

  • 困难地图最多使用 200,000 步。

  • 超困难地图最多使用 400,000 步。

这样的设置是为了测试 sample efficiency（数据利用效率）：在真实环境经验有限时，哪种方法学得更快、成绩更高。

作者将 MARIE 与五种方法比较：

  • MAPPO、QMIX 和 QPLEX：不使用 World Model。

  • MBVD 和 MAMBA：使用 World Model。

每种方法通常独立运行 4 次，并用战斗胜率作为主要指标。

作者还做了几组拆解实验：

  • 把每个 agent 的局部模型改成一个统一的全局模型，看 agent 数量增加后会怎样。

  • 去掉 Perceiver，检查全局摘要是否真的有用。

  • 替换 VQ-VAE 的 token 压缩方式。

  • 比较模型连续想象多步之后，预测误差累积得有多快。

论文还在 3 个 Multi-Agent MuJoCo 任务上进行了补充实验。这类任务让多个控制器共同操纵一个连续运动的物体。

实验结果怎样？

MARIE 在 agent 数量大于 3 的任务中表现尤其突出。例如：

  • 3s_vs_4z，训练 100,000 步后：MARIE 胜率为 73.0%，MAMBA 为 29.3%，其他对比方法为 0。

  • 3s_vs_5z，训练 200,000 步后：MARIE 为 78.4%，MAMBA 为 13.4%，其他方法为 0。

  • corridor，训练 400,000 步后：MARIE 为 71.0%，MAMBA 为 26.5%，不使用 World Model 的方法接近 0。

拆解实验表明：

  • 把所有 agents 塞进一个统一的全局预测模型后，agent 越多，训练效果下降得越明显。

  • 去掉 Perceiver 后，多个任务的成绩下降，说明局部模型仍然需要全局信息帮助。

  • VQ-VAE 固定生成 16 个 tokens，比把观察中的每个数值分别离散化更容易扩展到高维输入。

  • 连续预测多步时，MARIE 的误差比 MAMBA 累积得更慢。

MARIE 的代价是模型较大：World Model 约为 55.35 MB，MAMBA 约为 23.72 MB，而不使用 World Model 的对比方法不到 1 MB。不过，这个大模型只用于训练，不会随最终策略一起部署。

论文的主要实验只有 4 次独立运行；Transformer 逐步生成长轨迹时也会比较慢。因此，结果说明 MARIE 能提高有限数据下的学习效率，但还没有回答它在大型实时系统中的训练时间和计算成本。

Part II. 分布式 World Model

分布式 World Model 到底是什么？

“分布式 World Model”这个说法容易产生歧义，因为“分布式”可以出现在三个不同位置：

  • Distributed training（分布式训练）： 数据和计算分散在多台机器或多个节点上，大家一起优化一套模型参数。训练完成后，这个 World Model 仍然可能只在中心运行。

  • Distributed operation（分布式运行）： 不同 agents 分别观察环境、维护自己的内部状态、预测未来并作出本地决策，同时通过通信协调彼此的预测。

  • Distributed adaptation（分布式适应）： 模型部署以后，各节点根据本地新数据继续更新，再通过 federated learning、parameter sharing 或其他方式偶尔同步。

这三个概念可以组合，但并不等价。仅仅使用多台机器训练出一个中央 World Model，属于 distributed training；它还没有解决模型部署后如何在多个节点上观察、想象和决策的问题。

本文主要关心的是第二种：distributed operation。训练可以先在地面集中完成，部署后则由每颗卫星根据自己的局部信息运行 World Model。后续也可以加入 distributed adaptation，但它不是这个概念成立的前提。

共享预测规律，但不共享同一份“当前世界”

一种比较实际的设计，是先训练一套共享的 dynamics model，再把相同的模型参数部署到多颗卫星。这个模型学习一般性的变化规律，例如：

  • routing action 会怎样改变下一跳和后续 queue；

  • traffic、link availability 和 delay 怎样随时间变化；

  • 某种网络状态最终可能带来多少 reward 或 cost。

虽然模型参数可以相同，但每颗卫星看到的 observation 和历史不同，所以它们内部维护的状态也不同。这里把这种内部状态称为 local belief：它是某颗卫星根据自己已经看到的信息，对“网络现在可能是什么情况”的判断。

因此，“共享同一个 World Model”不等于“所有卫星认为世界完全相同”。更准确地说，它们可以共享一套预测规律，同时各自维护不同的 local belief。

一次完整的分布式运行过程

在每个决策时刻，每颗卫星可以按照下面的闭环运行：

  1. Local observation： 某颗卫星读取自己的 queue、可用链路、邻居状态和附近 traffic。

  2. Belief update： 它把当前 observation 与历史记忆结合，更新自己的 local belief。

  3. Information sharing： 它只把有必要的信息发给相关邻居，例如压缩后的 latent state、异常 queue、prediction error 或 uncertainty，而不是广播全部 raw telemetry。

  4. Information fusion： 收到邻居信息后，它修正自己的 local belief，补充自己直接看不到的网络变化。

  5. Imagined rollout： 它在 World Model 中尝试不同的 routing 或 resource-allocation actions，预测这些 action 在未来几步可能造成的 queue、delay、link 和 reward 变化。

  6. Local decision： 它选择预计长期结果最好的 action，在真实网络中执行。

  7. Correction： 新的真实 observation 到来后，它比较预测与现实，再次修正 belief，必要时更新模型或发送新的异常信息。

这里的 imagination 不是每颗卫星各自在一个完全封闭的小世界里想象。卫星 A 的 routing action 可能增加卫星 B 的 queue，B 的决定又可能影响 C。因此，imagined rollout 需要通过 message passing、graph aggregation、neighbor prediction 或其他机制，把跨节点影响包含进来。

什么不算分布式 World Model？

下面几种情况需要区分：

  • 多台 GPU 一起训练一个模型，但模型最终只在地面中心运行：这是 distributed training，不是分布式运行。

  • 多颗卫星安装相同模型，却始终把 observation 上传到中心，由中心统一预测和决策：模型被复制了，但实际推理仍然是 centralized。

  • 每颗卫星各自运行一个 World Model，彼此完全不交换信息，也不建模其他卫星的影响：这是多个 independent World Models，而不是一个能够协同预测的分布式系统。

本文所说的分布式 World Model，需要同时具备三个核心特征：

  • 每个节点能够根据 local observation 独立维护 belief 和继续运行；

  • 节点之间使用有限通信交换会影响共同未来的信息；

  • 各节点的 imagination 能够反映其他节点及其 actions 带来的影响。

Motivation：为什么需要分布式 World Model？

明确了上面的定义后，Motivation 就不再是“怎样用更多机器把一个模型训练得更快”，而是：为什么预测、imagination 和决策本身需要分布在多个节点上完成？

1. 现实世界本来就是分布式观察的

在许多多智能体系统里，没有任何一个 agent 能持续看到完整环境。

以卫星网络为例：

  • 一颗卫星最清楚自己的 queue、链路质量和附近 traffic。

  • 邻近卫星掌握它们各自的拥塞、故障和可用链路。

  • 地面站可能看到更大的网络范围，但它收到的信息会有传输延迟，也可能在某些时间无法与卫星连接。

因此，所谓“网络当前处于什么状态”并不是天然存在于某个中心位置，而是分散在不同节点的局部观察中。World Model 如果只学习其中一个节点看到的内容，就很容易把其他节点造成的变化误认为不可预测的噪声。

2. 全部集中到一个中央 World Model 并不理想

最直接的办法，是把所有 agents 的 observation 都传到中心，再训练和运行一个能够看到全局的 World Model。这样做概念上简单，但会带来几个问题：

  • 通信开销。 原始 observation、历史轨迹和模型状态可能很大，agent 越多，需要传输的数据越多。

  • 决策延迟。 数据必须先到中心，中心完成推理后再把结果发回。链路较慢或连接中断时，agent 不能及时行动。

  • 扩展困难。 agent 数量、输入维度和相互关系一起增长后，一个统一模型会越来越难训练。

  • 单点依赖。 中心节点或到中心的链路一旦不可用，整个系统的预测和决策能力都会受到影响。

MARIE 的实验体现了其中的扩展问题：把所有 agents 直接放入统一的 joint dynamics model 后，agent 数量增加时，学习效果明显下降。它采用 local dynamics 加 centralized aggregation，正是在寻找“局部建模”和“全局信息”之间的折中。

3. 每个 agent 完全独立建模也不够

另一个极端，是让每个 agent 只训练自己的 World Model，完全不与别人交换信息。这种方式通信成本低，也容易部署，但它忽略了 agents 之间的相互影响。

例如，卫星 A 把一批数据包转发给卫星 B 后，B 的 queue 会变长；B 随后的转发决定又会影响卫星 C。如果 A 的 World Model 看不到 B 和 C 的状态，它很难预测自己这次转发最终会造成多大的端到端延迟。

完全独立的模型还容易产生不一致的判断：A 认为某条路径畅通，B 却已经观察到该方向发生拥塞。每个模型单独看都可能是合理的，但这些局部判断放在一起，并不能形成协调的行动。

CoDreamer 的出发点正是这个问题：在 partial observation 下，其他 agents 的行动会让单个 agent 眼中的环境显得不断变化。它让 World Model 汇集邻居信息后，在需要合作和局部观察较强的任务中取得了更好的结果。

4. 分布式 World Model 想寻找中间道路

分布式 World Model 的 Motivation，可以概括为同时保留两种能力：

  • Local autonomy（本地自主性）： 即使暂时收不到其他节点的信息，每个 agent 仍能根据自己的观察和历史进行预测与行动。

  • Collective prediction（协同预测）： 当通信可用时，agents 交换对未来真正有帮助的信息，使各自的局部模型能够理解跨节点的影响。

这里真正困难的问题不是“要不要通信”，而是：

  • 应该分享 raw observation、压缩后的 latent state、prediction error，还是模型参数？

  • 什么变化值得立即发送，什么内容可以留在本地？

  • 应该发给所有 agents，还是只发给真正会受到影响的邻居？

  • 收到的信息可能过时、缺失或彼此冲突时，World Model 应该相信多少？

Efficient Information Sharing 的实验说明，全部分享并不一定最好；优先分享模型预测误差较大的少量经历，有时比传输所有样本更有效。这提示分布式 World Model 不应把通信仅仅当作固定的数据管道，而应学习判断“哪条信息最有价值”。

5. 为什么卫星网络特别适合研究这个问题？

卫星网络同时具有几个很特别的条件：

  • 拓扑具有可预测部分。 卫星轨道和许多可见性变化可以提前计算，没有必要让神经网络从零猜测。

  • 网络状态具有不可预测部分。 traffic arrival、queue、无线链路质量、gateway load 和临时故障仍然需要根据观测不断更新。

  • 信息天然分散。 每颗卫星首先得到的是本地 telemetry，不可能随时拥有零延迟的全网状态。

  • 通信资源有限。 星间链路的容量、可用时间、传输时延和能耗都限制了可以交换多少模型信息。

  • 系统必须持续运行。 即使与地面或部分邻居暂时失联，卫星仍需要作出本地决定。

这使卫星网络不适合“所有数据永远上传到一个中心”的假设，也不适合“每颗卫星彼此完全独立”的假设。它更需要一种介于两者之间的 World Model：确定性的 orbital dynamics 可以共享或直接计算，每颗卫星重点学习本地的不确定状态，再用有限通信交换会影响共同未来的关键信息。

因此，分布式 World Model 最核心的目标不是让每颗卫星都保存一份完整的全网模型，而是回答一个更实际的问题：

在通信受限、观察不完整和网络持续变化的条件下，多个局部 World Models 能否用少量信息交换，获得接近全局模型的预测与协调能力，同时保留本地自主性？
