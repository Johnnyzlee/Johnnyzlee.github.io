Learning goal: treat pandas as a labeled system for two-dimensional data and safely perform selection, cleaning, grouping, joining, reshaping, and time-series feature engineering. Every example uses a small trading panel and shows the table before or after an operation.
Series:Python · NumPy · scikit-learn

0. Understand the DataFrame before memorizing APIs

A DataFrame is a two-dimensional table: each row usually represents an observation, each column a variable, and the Index labels rows. A Series is a labeled one-dimensional array and also the type of one DataFrame column.

A common “long” quantitative table has one (date, asset) observation per row:

import pandas as pd

trades = pd.DataFrame({
    "date": pd.to_datetime([
        "2026-01-02", "2026-01-02", "2026-01-03",
        "2026-01-03", "2026-01-04",
    ]),
    "asset": ["A", "B", "A", "B", "A"],
    "sector": ["Tech", "Bank", "Tech", "Bank", "Tech"],
    "price": [100.0, 50.0, 102.0, 49.0, 101.0],
    "volume": [10.0, 20.0, 15.0, None, 12.0],
    "signal": [0.3, -0.2, 0.5, 0.1, None],
})

print(trades.to_string(index=False))  # index=False hides only the display index
print("shape:", trades.shape)
Expected output
      date asset sector  price  volume  signal
2026-01-02     A   Tech  100.0    10.0     0.3
2026-01-02     B   Bank   50.0    20.0    -0.2
2026-01-03     A   Tech  102.0    15.0     0.5
2026-01-03     B   Bank   49.0     NaN     0.1
2026-01-04     A   Tech  101.0    12.0     NaN
shape: (5, 6)

The table has five rows and six columns. NaN is a missing floating value, not zero.

1.1 Validate a unique key

duplicate_key = trades.duplicated(["date", "asset"], keep=False)
print(duplicate_key.any())
Expected output
False

The example key is unique. If a supposedly unique key is duplicated, investigate revisions, source errors, or a prior join before deleting rows.

2. Selection: loc uses labels, iloc uses positions

2.1 Columns, rows, and conditions

prices = trades["price"]                            # One column -> Series
small_table = trades[["date", "asset", "price"]]   # Several columns -> DataFrame

liquid = trades.loc[
    trades["volume"].gt(12),                        # Row condition: volume > 12
    ["date", "asset", "volume"],                   # Columns to return
]

print(type(prices).__name__)
print(liquid.to_string(index=False))
Expected output
Series
      date asset  volume
2026-01-02     B    20.0
2026-01-03     A    15.0

gt(12) is equivalent to > 12. Comparing a missing value with 12 returns false, so that row is excluded.

2.2 iloc and slice boundaries

print(trades.iloc[0:2, 0:3].to_string(index=False))
# iloc uses integer positions; 0:2 includes positions 0 and 1, not 2
Expected output
      date asset sector
2026-01-02     A   Tech
2026-01-02     B   Bank

A loc label slice usually includes its ending label; iloc follows Python's stop-exclusive positional slicing. State whether labels or positions are intended.

2.3 Create a column safely

selected = trades.loc[trades["asset"].eq("A")].copy()
selected.loc[:, "notional"] = selected["price"] * selected["volume"]

print(selected[["date", "asset", "notional"]].to_string(index=False))
Expected output
      date asset  notional
2026-01-02     A    1000.0
2026-01-03     A    1530.0
2026-01-04     A    1212.0

.copy() declares independent modification, and .loc makes the assignment target explicit. Avoid chained assignment such as df[df[“x”]>0][“y”] = ….

3. Missing data, conversion, and duplicates

3.1 Missing-value handling encodes an assumption

filled = trades.copy()
filled["volume"] = filled["volume"].fillna(0.0)  # Assume missing volume means no trade
dropped = trades.dropna(subset=["signal"])       # Require signal only

print(filled["volume"].tolist())
print(dropped[["date", "asset", "signal"]].to_string(index=False))
Expected output
[10.0, 20.0, 15.0, 0.0, 12.0]
      date asset  signal
2026-01-02     A     0.3
2026-01-02     B    -0.2
2026-01-03     A     0.5
2026-01-03     B     0.1

The zero fill is an example assumption. If missing means “not received,” zero fabricates an observation. Document a missingness rule for every important column.

3.2 Convert types deliberately

raw = pd.Series(["10", "bad", "30"])
numeric = pd.to_numeric(raw, errors="coerce")  # Unparseable bad becomes NaN

print(numeric.tolist())
Expected output
[10.0, nan, 30.0]

errors=“coerce” is convenient but hides the original bad value. Keep a failure mask such as raw[numeric.isna() & raw.notna()] for auditing.

4. groupby: agg versus transform

4.1 agg produces summary rows

sector_summary = (
    trades.groupby("sector", observed=True)
    .agg(
        observations=("price", "size"),
        mean_price=("price", "mean"),
        mean_signal=("signal", "mean"),
    )
    .reset_index()
)

print(sector_summary.to_string(index=False))
Expected output
sector  observations  mean_price  mean_signal
  Bank             2        49.5        -0.05
  Tech             3       101.0         0.40

mean ignores NaN by default, so Tech mean signal uses 0.3 and 0.5. agg reduces each sector to one row.

4.2 transform preserves row count

with_group_mean = trades.copy()
with_group_mean["sector_mean_signal"] = (
    with_group_mean.groupby("sector", observed=True)["signal"].transform("mean")
)
with_group_mean["demeaned_signal"] = (
    with_group_mean["signal"] - with_group_mean["sector_mean_signal"]
)

print(
    with_group_mean[["asset", "sector", "signal", "demeaned_signal"]]
    .to_string(index=False)
)
Expected output
asset sector  signal  demeaned_signal
    A   Tech     0.3            -0.10
    B   Bank    -0.2            -0.15
    A   Tech     0.5             0.10
    B   Bank     0.1             0.15
    A   Tech     NaN              NaN

transform returns one value per original row, so it can become a column. apply is flexible but harder to reason about and often slower; prefer vectorized methods, agg, or transform.

5. merge: define key cardinality first

metadata = pd.DataFrame({
    "asset": ["A", "B"],
    "country": ["US", "HK"],
    "market_cap": [500.0, 120.0],
})

panel = trades.merge(
    metadata,
    on="asset",                 # asset is the key in both tables
    how="left",                 # Retain every trades row
    validate="many_to_one",     # Left may repeat; metadata asset must be unique
    indicator=True,             # Record how each row matched
)

print(panel[["asset", "country", "_merge"]].drop_duplicates().to_string(index=False))
print("rows before/after:", len(trades), len(panel))
Expected output
asset country _merge
    A      US   both
    B      HK   both
rows before/after: 5 5

validate=“many_to_one” fails loudly if the metadata key is duplicated instead of silently multiplying rows. After a join, inspect row count, unmatched rate, and important totals.

  • left: retain the left table; common for feature mapping.

  • inner: retain only matches; may silently discard observations.

  • outer: retain all keys from both sides; useful for reconciliation.

  • concat: append along an axis without key matching.

7. Time series: sort, shift, pct_change, and rolling

Sort by entity and time before grouped time operations.

panel = trades.sort_values(["asset", "date"]).copy()
grouped = panel.groupby("asset", group_keys=False)

panel["ret_1d"] = grouped["price"].pct_change(fill_method=None)
panel["signal_lag1"] = grouped["signal"].shift(1)
panel["price_mean_2"] = grouped["price"].transform(
    lambda s: s.rolling(window=2, min_periods=2).mean()
)

print(
    panel[["date", "asset", "price", "ret_1d", "signal_lag1", "price_mean_2"]]
    .to_string(index=False)
)
Expected output
      date asset  price    ret_1d  signal_lag1  price_mean_2
2026-01-02     A  100.0       NaN          NaN           NaN
2026-01-03     A  102.0  0.020000          0.3         101.0
2026-01-04     A  101.0 -0.009804          0.5         101.5
2026-01-02     B   50.0       NaN          NaN           NaN
2026-01-03     B   49.0 -0.020000         -0.2          49.5

  • pct_change divides each price by its previous price within asset.

  • shift(1) places the previous signal on the current row.

  • rolling(2) here includes the current and previous price. A feature used before the current price is known may need another shift(1).

7.1 Build a forward-return target

panel["fwd_ret_1d"] = grouped["price"].transform(
    lambda s: s.shift(-1).div(s).sub(1.0)
)

print(panel[["date", "asset", "price", "fwd_ret_1d"]].to_string(index=False))
Expected output
      date asset  price  fwd_ret_1d
2026-01-02     A  100.0    0.020000
2026-01-03     A  102.0   -0.009804
2026-01-04     A  101.0         NaN
2026-01-02     B   50.0   -0.020000
2026-01-03     B   49.0         NaN

The row at time $t$ uses the price at $t+1$ for its target. Audit feature publication time, trading time, corporate-action adjustment, and the target interval together.

8. Cross-sectional ranks and a small factor workflow

factor = pd.DataFrame({
    "date": pd.to_datetime(["2026-01-02"] * 3 + ["2026-01-03"] * 3),
    "asset": ["A", "B", "C", "A", "B", "C"],
    "signal": [0.2, -0.1, 0.5, 0.4, 0.3, -0.2],
    "fwd_ret": [0.01, -0.02, 0.03, 0.02, 0.01, -0.01],
})

factor["signal_rank"] = factor.groupby("date")["signal"].rank(
    method="average", pct=True
)
daily_ic = factor.groupby("date")[["signal", "fwd_ret"]].apply(
    # Spearman correlation is Pearson correlation after ranking both variables
    lambda g: g["signal"].rank().corr(g["fwd_ret"].rank()),
)

print(factor.to_string(index=False))
print("daily IC:")
print(daily_ic)
Expected output
      date asset  signal  fwd_ret  signal_rank
2026-01-02     A     0.2     0.01     0.666667
2026-01-02     B    -0.1    -0.02     0.333333
2026-01-02     C     0.5     0.03     1.000000
2026-01-03     A     0.4     0.02     1.000000
2026-01-03     B     0.3     0.01     0.666667
2026-01-03     C    -0.2    -0.01     0.333333
daily IC:
date
2026-01-02    1.0
2026-01-03    1.0
dtype: float64

Selecting only the relevant numeric columns before apply prevents the grouping key from reaching the custom function. Ranking explicitly also avoids a dependency on the optional SciPy package. This toy data is deliberately perfectly monotone; real IC is not.

9. Performance and correctness

  • Prefer column operations, built-in groupby methods, and joins over iterrows().

  • apply is not an automatic accelerator; prefer vectorization, agg, or transform.

  • Project to needed rows and columns before expensive joins or groups; inspect df.memory_usage(deep=True).

  • category may compress repeated strings, but verify join and ordering semantics.

  • Never rely on implicit order. Sort explicitly before time operations.

  • For every merge, inspect cardinality, validate, row-count change, and unmatched rate.

  • For every lag or window, state whether the value is actually available at prediction time.

10. Interview checklist

  1. What does one row represent, and what is the primary key?

  2. What are each column's dtype and missing-value meaning?

  3. Is selection label-based or positional?

  4. Does the group operation reduce rows with agg or preserve rows with transform?

  5. Is a join one-to-one, one-to-many, or many-to-many?

  6. Is time sorted, and is shift moving in the correct direction?

  7. Are row count, date range, and important totals plausible afterward?

  8. Is there future leakage, survivorship bias, or unjustified filling?
